# 自动打开公众号与连续采集

在已登录、可交互的 Windows 微信桌面上，主服务输入或选择公众号完整名称，保留“自动打开主页”和“结束后关闭”，设置篇数后开始运行。0 篇表示遍历所选日期范围；文章数量、去重及资源选项沿用原流程。关闭“自动打开主页”可继续使用手动模式。

导航优先使用微信本地公众号搜索，未找到时使用“发现 → 搜一搜 → 公众号”。只接受完整名称匹配；同名结果要求人工确认。统一使用主页“全部”列表。程序不会自动登录、关注或发送消息。

设置 → 主页窗口 → 界面操作间隔：默认 0.5 秒、最低 0.5 秒。搜索、点击、滚动和关闭共用间隔；双击作为一次操作，加载等待已超过间隔时不额外等待。网络和单篇任务间隔仍独立。

主流程接口新增 `targetAccountName`、`accountMode`（`automatic`/`manual`）、`closeHomeAfterTask`。旧请求不传模式仍为手动模式。自动模式必须提供完整名称。补采从所选文章推导公众号；仅补本地图片或阅读页时不操作微信。

结束、异常和取消都会等待前台退出后清理登记的标签及新开的公众号会话，保留微信主程序和其他页面。界面“页面清理”单独显示清理结果。身份不能确认时保留页面并报告，不按窗口名称强制关闭。任务清理期间不能启动另一轮。

忽略目录 `data/runtime/navigation/` 保存会话身份和动作时间，不保存登录凭据。异常退出后，下轮会先核验上轮页面；未确认前台已停止时阻止新的导航。每轮任务目录的 `task-config.json` 保存业务选项和界面操作间隔。

测试：`.venv\Scripts\python.exe -m unittest discover -s tests -v`。实际桌面验收仍需验证打开、读取卡片、采集后关闭，并截图检查主服务布局。
